# CLAUDE.md

Repo-wide agent guidelines live in [AGENTS.md](AGENTS.md). Read it first.

This workspace holds the `wire/` and `sdk/` Rust crates, Python bindings under `foreign/python/`, and the native Node client under `foreign/typescript/`. All three SDKs consume the Rust-owned wire contract and the shared BDD scenarios. A Go client is in progress under `foreign/go/`, which ports the wire contract in full and has started the client itself in `laser/` with connect, TLS resolution, capability negotiation, the managed command path, and the key-value, query, fork, graph, session-read and authorization surfaces, publishing, consuming, replay, typed records, the provenance headers, AGDX agent messaging, the agent gates, the registry and router, request/reply correlation, memory, context assembly, session writes, the bridge value mappings, request/reply, dead-letter writes, folding the agent registry off the log, server-side consumer filters with the saved-filter catalog, the projection, binding and writer-schema registries, materialization, the change feed, the per-conversation context scope, claim-checked bodies, local state stores, swarm activity, crash context, edge authorization, the agent topology bootstrap, dead-letter redrives, chunk stream reassembly, a batching producer, record signing with its key registry, action governance with chained policy evidence, approvals, and the shared retry schedule. It is listed in docs/parity.md under its own capability section, has examples under examples/go/, and a conformance runner under bdd/go/.

Area skills are under `.claude/skills/`. Start with [laser-sdk-overview](.claude/skills/laser-sdk-overview/SKILL.md). TypeScript work also loads [typescript-sdk](.claude/skills/typescript-sdk/SKILL.md). Consumer filters (`sdk/src/filters/`, `wire/src/filter/`, and their TypeScript and Python peers) load [consumer-filters](.claude/skills/consumer-filters/SKILL.md).

The [AGDX specification](docs/agdx.md) defines streams, topics, headers, envelopes, sessions, queries, and limits. `laser-wire` implements these types, and `wire/fixtures/` defines their expected encoding.

Client defaults each have one owning page: [connect timeout](docs/connect-timeout.md), [publish recovery](docs/publish-recovery.md), [producer statistics](docs/producer-statistics.md), and [client behavior](docs/client-behavior.md). Link to them instead of copying their text.

Keep affected documentation consistent with authorized code or contract changes. This includes `README.md`, `sdk/README.md`, `wire/README.md`, `AGENTS.md`, this file, relevant `.claude/skills/*`, `docs/*`, and the AGDX specification. Do not report completion while affected documentation is stale.

Materialization setup lives in `sdk/src/materialize.rs`, `foreign/python/src/materialize.rs`, `foreign/typescript/src/managed/materialize.ts`, and `foreign/go/laser/materialize.go`. The shared scenarios are `bdd/scenarios/materialization.feature` and `bdd/scenarios/operational_sql.feature`. Keep append and keyed history, rejection policies, captured-target readiness, and explicit raw SQL dialects aligned in every client. Read `docs/client-behavior.md` from the repository root for the public contract.
