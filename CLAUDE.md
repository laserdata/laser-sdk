# CLAUDE.md

Repo-wide agent guidelines live in [AGENTS.md](AGENTS.md). Read it first.

This workspace holds the `wire/` and `sdk/` Rust crates, Python bindings under `foreign/python/`, and the native Node client under `foreign/typescript/`. All three SDKs consume the Rust-owned wire contract and the shared BDD scenarios. A Go client is in progress under `foreign/go/`, which ports the wire contract in full and has started the client itself in `laser/` with connect, TLS resolution, capability negotiation, the managed command path, and the key-value, query, fork, graph, session-read and authorization surfaces, publishing, consuming, replay, typed records, the provenance headers, AGDX agent messaging, the agent gates, the registry and router, request/reply correlation, memory, context assembly, session writes, the A2A and MCP bridges and the AG-UI value mappings, request/reply, dead-letter writes, folding the agent registry off the log, server-side consumer filters with the saved-filter catalog and the consumer group handle that owns a policy, fanning work out to every capable agent under a gather policy, the projection, binding and writer-schema registries, materialization, the change feed, fold snapshots, the per-conversation context scope, claim-checked bodies, local state stores, swarm activity, crash context, edge authorization, the agent topology bootstrap, dead-letter redrives, chunk stream reassembly, a batching producer, record signing with its key registry, action governance with chained policy evidence, approvals, durable intents with their quorum fold, the session layout that routes agent work off the shared lane, session leases with their heartbeat loop, cluster node routing for the managed band, stream and topic administration, the operator control fold with its write side, the session state document, recorded model and tool calls, submitting work to an agent, session budgets with their admission gate, and the shared retry schedule. It is listed in docs/parity.md under its own capability section, has examples under examples/go/ (a small fraction of the other SDKs' per-scenario set), and a conformance runner under bdd/go/ covering every shared feature file, run against a live Apache Iggy server in CI by ci-go.yml's `bdd-go` job, through the same scripts/run-with-test-iggy.mjs helper and the same pinned server release the TypeScript runner uses; every scenario passes or skips for want of a managed backend. `foreign/go/IMPLEMENTATION_STATUS.md` is the authoritative, source-verified inventory of what is implemented, partial, missing, and blocked: as of its last update, no whole subsystem is missing from the agent-orchestration layer. `Contract`, `Scatter` and the workflow engine all exist (the declared-steps DAG, saga compensation, exclusive fenced steps with reassign-on-timeout, and the plain-code `WorkflowRun` form), as do submitted-session pickup, the spawned-agent lifecycle (`Laser.SpawnAgent`/`AgentHandle` with its capability card and presence, governor, memory-consolidation tick, and the signing/verifying gates on both the agent and reply sides), `ConcurrencyPolicy`, `WarmDedupPolicy`, and the Kv lease/fence client. Since then principal-bound routing with the presence fold, inbox routing, the shared reply dispatcher, mandatory operator pause with durable parking and recovery, and semantic memory with its embedder/reranker/summarizer seams have all landed, so every capability gap that file tracked is closed except three that are blocked or architectural; approval parking has since landed too, so an approval gate under `RuntimeOptions.EnforceControl` parks the record and replays the handler with the decision instead of holding the consumer. Session writes are now bound to the lane identity the handle was pinned to, so a handle retained across a recreated stream or topic refuses them as `laser.StaleLaneError` instead of appending to the replacement. What remains is BDD coverage and examples. Read that file, not this paragraph, for Go's current state.
