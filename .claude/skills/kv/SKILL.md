# Key-value store (client)

The TypeScript peer is `foreign/typescript/src/managed/kv.ts` over `src/wire/kv.ts`, including CAS, fenced CAS, scans, expiry, patch, holder-scoped lease renewal, and barriered reads. Python binds the same `Lease` and `MutationPosition` through `foreign/python/src/kv.rs`.

A small managed key-value store next to the query layer, reachable on the one Iggy connection. Like `query`, the SDK ships only the **client**. The store lives in `laser-plane`, shipped by Laser Stack and LaserData Cloud, and the Iggy server forwards the operations. All of it is behind the independently selectable `kv` feature: private managed-command plumbing is shared without a semantic feature dependency. Wire: the AGDX spec

Authorization: ordinary KV ops are gated by the server-side capability layer (`kv:read` for get/scan/exists/namespaces, `kv:write` for set/cas/patch/expire/copy/move, `kv:delete` for delete/delete-many), scoped by the **namespace** as the keyed resource. Lease acquire, renew, and release use `kv_lease:admin` on the coordination namespace. Fenced CAS additionally requires `kv_fence:read` on its `fence_namespace` beside `kv:write` on the target namespace. The streaming server derives `(feature, action)` from the command code and checks grants before forwarding (see the wire `authz` module and the AGDX spec's namespace-scoped grant rules). A **memory read** rides this as `kv:read` on the materialized memory namespace. A memory **write** is a streaming publish on the memory topic (gated by Iggy `send_messages`), not a KV capability.

## What ships here (`sdk/src/kv/mod.rs`, the fluent builders in `sdk/src/kv/client.rs`)

- `Laser::kv(namespace)` -> a cheap namespace-scoped `Kv` handle owning a `Laser` clone (`'static`, so it moves into a spawn or stores in a durable `StateStore` seam). `Laser::kv_namespaces()` lists every namespace holding at least one entry for the caller (read-only, user-scoped, for tooling/UI browsing).
- Reads: `get` (`Option<Vec<u8>>`), `get_entry` (`KvEntry` with expiry), `get_entry_at_least(key, MutationPosition)` (barriered takeover read, `KvError::Stale`, never absent, when the fold cannot catch up), `get_typed::<T>` (JSON-decode), `get_as::<C, T>` (decode with any `Decoder`), `exists(key)` (`Option<KvMetadata>`: version/expiry/size without transferring the value, the cheap precondition check before a large fetch).
- `set(key)` builder: `.bytes(impl AsRef<[u8]>)` / `.json(&v)?` / `.msgpack(&v)?` / `.encode_with::<C, _>(&v)?` (any `Codec` - Avro / Protobuf / Arrow / your own), optional `.ttl(Duration)` / `.expires_at(epoch_micros)`, then `.send()`. Values are opaque bytes, so the codec is the caller's choice on both ends.
- Compare-and-swap on the same `set` builder: `.expect_version(n)` (apply only if the key holds version `n`) or `.expect_absent()` (create-if-absent), then `.commit().await -> u64` (the new version). A precondition miss is `KvError::VersionConflict { current: Option<u64> }` (`LaserError::is_version_conflict()`) carrying the present version (`None` = absent), so the caller re-reads and retries. `KvEntry.version` (from `get_entry`) is the compare token, and `0` means an unversioned store.
- `cas_fenced(key, fence_namespace, fence_key, fence_token)` builder: the same value/precondition/expiry chain as `set`, finished with `.commit().await -> u64`, but the write also requires a live lease in `fence_namespace` and its fence sequence to equal `fence_token`. This is the at-most-one-effective-writer gate for an exclusive workflow step (see `workflow.rs` in [agent-runtime](../agent-runtime/SKILL.md)). An expired, released, or stale lease is `KvError::LeaseLost`. A target precondition miss remains `KvError::VersionConflict`.
- `expire(key, ttl)` sets or clears an entry's expiry in place without rewriting the value, returning its unchanged version. `patch(key, patch_bytes)` applies a codec-specific merge patch (a JSON merge patch over a JSON value, for instance) without transferring the whole object, returning the new version.
- `lease(key, holder, ttl) -> Lease { token, granted_ttl, position }` acquires a holder-scoped bounded-TTL lock and returns the barrier position for takeover reads. The Rust convenience path, inherited by Python, uses a cached dedicated coordination connection. Acquisitions are serialized per client. A timed-out request actively retires that connection, and an ambiguous acquisition keeps the gate through the requested TTL even if its calling future is dropped, so a caller cannot immediately mint a fresh identity. A live lease always conflicts. `renew_lease(key, holder, token, ttl)` extends it with the same token and a fresh position. `release(key, holder, token) -> bool` removes it early. Long-running holders renew before the granted TTL expires. `WORKFLOW_FENCE_NAMESPACE` is public for handlers using the default workflow coordination namespace.
- `delete(key)` -> `bool` (existed). `delete_many()` builder (`.prefix` / `.range` / `.key_contains`, same bounds as scan) -> count removed. No bounds clears the namespace. `scan()` builder: `.prefix` / `.range` (byte order) / `.key_contains(str)` (valid-UTF-8 keys only) / `.limit` / `.cursor` -> `.fetch()` (one `KvPage`) or `.entries()` (walk all pages by cursor). Both `scan()` and `delete_many()` also take `.conversation(id)` (the conversation lens): narrow to the rows one conversation wrote over a memory-view namespace, a filter on the auto-projected `conversation_id` field. A generic entry carries no conversation and is left out of a conversation-filtered scan.
- `copy_to(key, to_key)` / `move_to(key, to_key)` builders (`.into_namespace(ns)` for a cross-namespace target, then `.send() -> u64` the destination's new version): one backend transaction under the store's single-writer guard, move is copy plus source delete, absent-or-expired source is `KvError::NotFound`, destination overwritten (guarded copy composes `exists` + `cas`), the value moves with its remaining expiry. `get_many(keys) -> Vec<Option<Vec<u8>>>` rides the mixed-operation batch (`Laser::execute_batch`, `AGDX_BATCH_CODE` = base+20, up to `MAX_BATCH_OPS` = 64 items, per-op results, never a transaction, nested rejected). Python mirrors all three (`copy_to`/`move_to` with `to_namespace=`, `get_many`).
- Keys / values cross the API as `impl AsRef<[u8]>` in, `Vec<u8>` out (no `bytes` crate leak). `KvEntry { key: Vec<u8>, value: Vec<u8>, expires_at_micros, version, scope }`, `key_str()` gives the UTF-8 view when the key is valid UTF-8, `decode_value`/`decode_value_with::<C, _>` decode the value. `scope` is `Option<Box<MemoryRowScope>>`, present only on a memory read-view row and `None` on a generic entry: the memory provenance (kind, agent, user, app, conversation) plus a `SourceRef` source pointer to the origin log record, boxed so a generic entry stays small. Agentic memory recall reads these back off the shared KV read view.
- `execute_kv(namespace, code, request)` (crate-internal) gates on `capabilities.kv.available`, set by an initial or refreshed `AGDX_HELLO` announcement only while the managed backend reports ready. Lease, renew, release, fenced CAS, and `get_entry_at_least` additionally require `capabilities.kv.fenced_leases` before encoding or sending. `Laser::execute_batch` inspects raw inner items and applies the same must-not-send gate.
- `FencedLeaseClient` is generic over `ManagedKvTransport`. Hold it as `SharedKvTransport` (`Arc<dyn DynManagedKvTransport>`) when the transport is a runtime choice, since `ManagedKvTransport`'s `async fn`s give it no vtable. Every `ManagedKvTransport` implements the object-safe trait and the `Arc` implements `ManagedKvTransport` back, so nothing about framing or retry changes. `FencedLeaseClient` in `coordination.rs` owns a dedicated resettable transport and prepares one transport-bound `PreparedMutation` with a stable operation id. `PreparedMutation::ambiguous_recovery()` returns the typed `AmbiguousMutationRecovery` for its operation. Readiness, authentication, and capability failures happen before the ambiguous send window. A timeout actively shuts down the retired Iggy client before reconnect. `AmbiguousMutation` is not generically retryable: repeat the same prepared renew/release operation, reconcile fenced CAS through its target precondition, and wait the acquisition's requested maximum TTL before preparing another acquire because the transport provides no dedup guarantee and a lost grant reply carries no token.

## Wire (the managed KV contract)

- One managed command **per op** in the KV block (base `AGDX_KV_BASE` = 1_000_300): get (+0), set (+1), scan (+2), delete (+3), delete-many (+4), namespaces (+5), CAS (+6), exists (+7), expire (+8), patch (+9), lease (+10), release (+11), fenced CAS (+12), copy (+13), move (+14), and lease renewal (+15). Ordinary requests use `KV_OP_VERSION = 1`. `KvLease`, `KvLeaseRenew`, `KvRelease`, and `KvCasFenced` use `KV_LEASE_OP_VERSION = 2` under `KV_FENCED_LEASES`. Required reshaped fields have no decode defaults.
- Requests are named-field CBOR and carry `v` plus `namespace` where scoped. `KvGet.min_position` is an optional `MutationPosition { topic_generation, partition, offset }`. `KvCasFenced` adds `fence_namespace`, `fence_key`, and `fence_token`. Lease acquire/renew/release carry `holder_id`. Acquire and renew may carry delegated `subject_user_id`. `KvOutcome::Leased` and `Renewed` return token, granted TTL, and position. `Released(bool)` is idempotent for a missing current lease. `KvError` includes `VersionConflict`, `LeaseLost`, and `Stale { required }`. `KvEntry` carries `version: u64` (skip-when-zero).
- `key` and `value` are arbitrary bytes, a CBOR byte string (byte-exact). Scan bounds (`prefix`/`start`/`end`/`cursor`) are bytes, `key_contains` is a string.
- The managed deployment wraps each op in the shared `ForwardedCommand { user_id, client_id, correlation, read_all, command_code, payload }` keyed frame (also used by registry browse, and `AGDX_QUERY` keeps its own `ForwardedQuery`), stamping identity. The forwarded-frame shapes live in laser-wire (`wire/src/forward.rs`). The dispatch and the backend are managed-side behavior, not in this repo.

## Conventions + caps

- **Keys** are non-empty arbitrary bytes, max 512 B. **Values** are arbitrary opaque bytes, max 8 MiB. A lease `holder_id` is non-empty and at most `MAX_HOLDER_ID_BYTES = 128` UTF-8 bytes. Its charset is otherwise unrestricted. Fence tokens are nonzero. A requested lease TTL, on acquire and renew alike, must fall in `MIN_LEASE_TTL_MICROS = 1_000_000` ..= `MAX_LEASE_TTL_MICROS = 300_000_000`: the request is a maximum the store may clamp down but never up, so the range is validated on the request before the round trip instead of clamped after it. Scan limit is 1000 (default 100). Rust and TypeScript validate these shapes before sending and reject version 1 lease-family payloads during decode.
- A **namespace** is a logical bucket (keys unique within it, scans scoped to it, isolated by managed RBAC). Expiry is lazy-on-read + swept, managed-side.
- KV requires LaserData Cloud or Laser Stack. Apache Iggy without a managed backend reports `capabilities.kv.available` as false and calls return `LaserError::Unsupported`.
- **CAS is backend-gated.** Plain CAS uses `feature::KV_CAS` / `capabilities.kv.cas`. The full holder-scoped lease contract uses `feature::KV_FENCED_LEASES` / `capabilities.kv.fenced_leases` and subsumes the older `KV_CAS_FENCED` bit, so capability folding must set `cas_fenced` when either bit is present. Binary hello and the HTTP `KvCapsView.fenced_leases` field must agree.

## Rules specific to this area

- KV is mutable **point state**, NOT a message log: it does not ride Iggy log. Do not route set/delete through topics. (Contrast `query`, whose writes ARE log appends.) The deployment picks the durability and multi-node options.
- The SDK is **client-only**: never add a KV backend/worker here. Storage, expiry, and dispatch are server-side concerns.
- Keep boundaries crisp: log = history/stream, KV = point state, AgentFS (future) = per-agent filesystem/workspace. Do not conflate.
- KV is a **primitive**, not the agent "memory" abstraction (which is the `Memory` trait in `sdk/src/memory.rs`). The two are distinct: memory (including its named-item altitude `MemoryHandle::{set,fetch,update,remove}`) always rides the memory topic as durable records, which a deployment materializes into the versioned KV read view. `Laser::kv` is the raw primitive, a direct point store with no stream. Add memory semantics behind the `Memory` trait - never rename `kv` to `memory`.
- Tests live in-module (`sdk/src/kv/client.rs` `#[cfg(test)]`): codes, envelope round-trips, key validation, error mapping. BDD names, `.expect("msg")`.
